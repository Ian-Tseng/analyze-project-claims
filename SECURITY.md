# Security Policy

## Supported versions

Security fixes are provided for the latest published release. Please update to
the latest version before reporting a problem that may already be fixed.

## Report a vulnerability privately

Do not open a public issue and do not use the internal problem reporter for a
suspected vulnerability.

Use **Security > Advisories > Report a vulnerability** in this repository.
GitHub private vulnerability reporting keeps the report visible to the
maintainer while it is triaged and repaired.

Include only what is needed to investigate:

- affected version and installation method;
- impact and realistic attack conditions;
- minimal reproduction steps or a small proof of concept;
- suggested mitigation, if known.

Do not include credentials, private project data, or unrelated personal data.
If the private reporting button is temporarily unavailable, open a public issue
that asks for a private contact channel without disclosing vulnerability
details.

## Disclosure process

The maintainer will validate scope, coordinate privately when more information
is needed, prepare a tested fix, and publish a new immutable release. Public
disclosure should wait until affected users can update. Submission does not
guarantee a particular response or remediation timeline.

Ordinary non-security defects may use public GitHub Issues after reviewing the
exact content that will be posted.
