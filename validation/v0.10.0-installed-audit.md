## Using the plugin and checking fresh activation

Clarification recorded 2026-09-16: the untested fresh-conversation claim is
an evidence gap. It does not make a verified installation unusable.

| Observation | What it establishes |
| --- | --- |
| The current host catalog exposes the expected plugin path and version | Current-session discovery |
| A helper runs from that verified installed path | Execution of that helper |
| A new conversation discovers and explicitly uses the plugin | Fresh-conversation discovery and use |
| A newly started application process discovers and uses the plugin | Discovery and use after a full process restart |

When the current session exposes the requested version and its helpers run,
ordinary use can continue. To check the open fresh-conversation claim, start
a new conversation, invoke the skill explicitly, and record the observed
package path, version and task outcome. A full application restart is a
separate, stronger startup check; closing every window is not a universal
prerequisite for current use. If the new session exposes an old or missing
package, inspect the host's discovery state before claiming activation.

These distinctions clarify the verification procedure. They do not change
this dated audit's untested activation status or establish live hook behavior.

## Reusable operational lesson

A marketplace pinned to an old immutable ref can refresh successfully without
advancing version. Inspect the configured ref and snapshot commit. When the
user authorizes an exact newer version, use the native host's supported source
reconfiguration and verify the installed release identity afterward. Preserve
rollback information and compare unrelated installation entries. If the pin
and installation already match the requested release, no reconfiguration is needed.

Compare tracked product content and its package manifest, excluding Git's
clone administration files. Keep native listing, direct helper execution,
fresh host activation and complete lifecycle verification as separate claims.
Reopen the conclusion if the source ref, release identity or installed bytes differ.

This is a bounded operational lesson from one update, not independent validation
of all hosts. Its personal workflow counterpart was saved outside the released
package; no installed release files or accepted-map content were customized.
